# Every board explains how to view it

## Why
A board is a git repository of YAML and markdown. Someone who clones it, or opens it on GitHub,
sees `projects/` and nothing that says what it is or how to see it as a board. The user asked on
20 Oct 2026 for every board to carry a README that walks a reader from nothing to the visual
board, written when the board is created.

## Design

### What the README says
Generated by kanbanr, in plain words, for someone who has never used it:
1. **What this is.** "This repository is a kanbanr board: the plan, the reasoning and the evidence
   for <projects>, as plain YAML and markdown. kanbanr reads it; you can too."
2. **The projects on it**, one line each (name and description), from the board.
3. **See it as a board** (the monitor):
   - install kanbanr: the installer one-liner for macOS/Linux and for Windows, or `cargo install`
     from the repository;
   - clone this repository;
   - `kanbanr serve --data-dir <the clone>`, then open http://127.0.0.1:8080. It is read-only
     unless started with `--allow-writes`.
4. **Or in the terminal:** `kanbanr board --data-dir <the clone> --project <p>`, and
   `kanbanr feature show <CODE>`.
5. **Changing it:** the CLI (or the monitor with `--allow-writes`) is the one writer; changes reach
   others through this repository's git remote. Do not edit the YAML by hand.
6. A link to the kanbanr documentation.

### Kept current, never overwriting what people wrote
- The generated text sits between `<!-- kanbanr:readme:start -->` and `<!-- kanbanr:readme:end -->`.
  Anything outside the markers is the board owner's and is never touched.
- A board with no README gets one; a README without the markers gets the block appended once.

### When it is written
- **On creating a board** (the first commit of a new data repository): the README is part of it.
- **When projects change** (a project is created, renamed or deleted): the block is regenerated in
  the same commit.
- **Existing boards:** `kanbanr readme` writes or refreshes it now; `kanbanr doctor` warns once
  about a board with no generated README, naming that command.

### Components and files
- `api/crates/kanbanr-core/src/boardreadme.rs` (new): `render(store) -> String`,
  `apply(existing: Option<&str>, block: &str) -> String` (the markers, preserving outside text),
  `write(store) -> Result<bool>` (changed or not).
- Core: the data repository's creation and the project create/rename/delete paths call `write`.
- `api/crates/kanbanr-core/src/doctor.rs`: the "no README" warning.
- `api/crates/kanbanr-cli/src/main.rs`: `kanbanr readme`.
- Docs: getting-started (what a new board contains), housekeeping, cli.md, CHANGELOG.
